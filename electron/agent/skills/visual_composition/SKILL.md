# Visual composition and critique

Read this guide for new frontend composition, a requested visual refinement, or a critique of a rendered interface, illustration, or 3D presentation. It applies only to relevant visual work. Combine it with the selected website profile where one exists, browser_verification for functional/layout observations, and threejs for a 3D subject. It does not select or upgrade a design profile, activate MAX, introduce another model call or independent critic, or grant implementation permission. Under None, apply relevant visual judgment to the human's visual request without activating website-profile workflows. Honor diagnosis-only requests.

This guide teaches decisions and observation. It provides no page template, section sequence, color palette, font pairing, default camera, asset pack, animation, decorative motif, or fixed amount of content. Derive the presentation from the subject, audience, purpose, references, and user constraints. Preserve established identity for repairs and additions unless redesign is authorized.

When substantial browser work includes responsive composition, interactive states, or user-flow verification, read the registered browser_verification skill before implementing or running the checks. Reuse it if already successfully read and current. It explains launch routes, action/assertion input, visibility, and responsive evidence; do not infer those mechanics from this visual guide alone. This is an instruction to read relevant existing guidance, not a selection gate, new model call, or separate review stage. A standalone visual assessment with no browser behavior in scope does not require it.

## 1. Establish the intended experience

For several dependent deliverables, material ambiguity, or changed priorities, read task_planning. Routine creative decisions in an open brief remain yours; this reference adds no concept approval, separate planner, or review gate.

Identify what the viewer should understand, notice, and do. Use the actual subject and content, not an assumed identity from its name. Honor brand requirements, references, scope, theme, image-source restrictions, accessibility, and technical constraints. Inspect supplied references when available and separate visible facts from inference. For an open creative brief, make useful visual decisions independently; ask only for missing information that materially changes the result.

Translate words such as premium, attractive, playful, restrained, or technical into observable qualities for this subject. Premium can mean a coherent silhouette, precise type, carefully selected imagery, deliberate spacing, readable surfaces, or well-executed interaction. A dependency, expensive effect, dark surface, gradient, glass panel, or many sections does not establish quality by itself. Do not turn a loose quality request into a mandatory approval process or unbounded research exercise.

## 2. Compose around meaning and hierarchy

For a sticky or pinned composition, budget the actual visible height beneath measured header/footer chrome, safe-area insets and comfortable margins. Measure its complete readable content after fonts/media settle; viewport units or a width breakpoint alone do not establish fit. If it cannot fit, recompose or divide its story into readable states, keep supporting detail in natural flow, or release the lock on short windows. Re-evaluate when content, fonts, orientation or zoom changes. Preserve essential text size and the chosen effects; do not mask overflow or remove meaning. Normal reading sections can extend beyond one screen. This fitting rule applies to relevant visual work in every profile and does not introduce MAX libraries or design workflow under None.

### Layout first for a new whole website

With a selected website profile other than None, resolve the layout before writing website source. Use the existing set_design_brief storyboard; do not add a planning document, approval stage or model call. This also applies to a static new website. Repairs, additions and faithful recreations retain their requested identity and scope.

For an open-ended new website or standalone hero, use the registered website_layout_options skill for two concise internal design briefs developed to comparable depth, a selection reason and the selected layout blueprint. The same skill supports requested options-only planning without constructing a website. Preserve explicit human layouts, faithful recreations, repairs and additions; under None there is no automatic two-option workflow. It provides decision questions, not a layout menu, template, separate model call or approval stage.

Keep the fuller chosen plan in the current conversation. The existing construction storyboard is a compact digest: selected plan first, followed by short alternatives labeled A and B and the selection reason; label the unused option not for construction. These are public design summaries, not private reasoning transcripts. Compose the digest within the existing 3,000-character storyboard limit without unfinished sentences; the expanded option descriptions and blueprint do not have to fit there. Use the existing comparison only for the selected proposal, then inspect implementation drift within the existing allowance. Do not claim uniqueness without evidence.

Record the chosen plan concretely: what occupies the first viewport, the headline/action/media relationships and what the media communicates; each intended section's content purpose and composition in reading order; how adjacent areas connect; and the mobile ordering/cropping/control placement. Tie the important spatial decisions to a content reason: the visitor's question, the evidence that answers it, and the relationship the arrangement makes easier to understand. Group information by that relationship before deciding how many blocks or columns it needs. Default can express this in a compact paragraph. Medium adds hierarchy, density and the interaction that makes the visual idea useful. MAX adds motion to the chosen architecture rather than choosing an architecture to fit effects. A title such as editorial, premium or immersive is not a layout plan. Required content does not dictate its order, grouping, number of columns or visual treatment.

Orvix displays the recorded storyboard and comparison outcome directly in the assistant chat before construction. Write both option summaries and the selection reason clearly enough for the human to read there. This is an informational update, not a request for approval; continue with the selected direction when construction is allowed. Do not duplicate the same summary in another assistant message.

Keep the document source in a logical reading order. CSS visual reordering does not change keyboard or screen-reader order; an unusual composition must still have a coherent navigation sequence on desktop and mobile.

Build that chosen arrangement rather than reverting to a convenient component scaffold. During the existing desktop/mobile inspection, compare the rendered hero and section rhythm with the storyboard. If implementation drifted, correct the concrete mismatch within the existing revision allowance. A distinct proposal is not evidence that the built page is distinct. Do not claim universal uniqueness from one sample or treat a structural similarity cue as proof of copying.

Keep supporting image discovery proportional to construction. Start with one targeted subject query; if unsuitable, try one broader query, then choose from usable results or disclose the missing imagery. Reuse successful direct URLs and cached provider failures. Do not repeatedly fetch large stock-photo search pages or inspect browser runtimes just to locate an image URL; use the available search/preview tools. Respect an explicit source restriction and report an unavailable provider instead of silently substituting one. A new human request for additional image research may warrant further searches. During the existing preview, inspect whether each selected image actually shows the intended subject. A reachable URL alone does not prove relevance.

For Design MAX, also make the storyboard's content and media decisions observable: what each developed area explains, what its principal visual shows, and how its movement changes the visitor's understanding. Keep the section count and motion policy in the selected MAX skill; this shared guide adds no MAX obligations to Default, Medium or None. A builder-invented concept is a proposal to judge against the human brief, not a reason to accept arbitrary decoration as subject-specific design.

Give the principal subject and primary action appropriate prominence. Evaluate their scale, placement, contrast, surroundings, and relationship to supporting content. A model should be large enough to appreciate its important forms at the intended distance; a product or story should remain understandable without reading implementation notes. Choose what to emphasize and what to subordinate. Multiple elements need not compete at equal strength.

Use typography as a hierarchy of meaning: readable body text, distinguishable headings and labels, intentional line lengths, spacing, and alignment. Choose type for this identity and content; unusual fonts or oversized headings are not automatically better. Check actual rendered wrapping, density, and rhythm. Keep text legible across its backgrounds and states, including muted text and controls.

Use spacing and grouping to make relationships clear. Whitespace can be intentional; assess whether it supports focus, pacing, and readability or leaves a section apparently unfinished. Do not fill every gap with decoration. Avoid meaningless panels, repeated cards, detached labels, or empty scenes added only to increase scope. Each requested area should serve a purpose and receive treatment proportional to that purpose. A simplified composition can be complete; a scaffold cannot be called finished merely because it occupies the page.

## 3. Develop coherent visual craft

Choose color, surface, imagery, iconography, and geometry as a connected visual language. Check contrast and tonal separation in the rendered result. Similar dark values can hide a subject; indiscriminate borders or shadows can make every element equally prominent. Apply material response and lighting so important forms are readable and surface differences make sense. Avoid adding arbitrary ornament to hide weak proportions or composition.

For a character or 3D object, inspect silhouette, connected forms, proportions, expression, clothing/surface transitions, orientation, and contact/shadows. Distinguish a deliberate stylization from an accidental primitive assembly. Refine the major forms before microdetail, following threejs for engineering. A polished stage cannot compensate for an incoherent subject. Conversely, a good model still needs camera framing and surrounding UI that serve its intended presentation.

Choose relevant visual assets under the user's source constraints. Do not substitute unrelated images, invent business facts, claim reference fidelity without evidence, or present placeholders as final assets. Keep internal construction notes, geometry names, library versions, camera coordinates, test scores, and process explanations in the delivery report or developer documentation unless the user wants an educational/technical product. Preserve useful controls, attribution, accessibility, and truthful failure feedback in the experience.

## 4. Make motion and interaction meaningful

Associate motion with an identifiable relationship, state, discovery, or user action. Judge whether the actual change can be perceived and understood, not merely whether a timeline or library exists. A reveal must expose useful content; a pinned scene must frame its intended area and sustain meaningful content through the sequence. Follow the matching engineering skill for implementation.

Do not add auto-rotation, perpetual accents, scroll locking, or another dependency simply to demonstrate activity. Preserve content, controls, and subject comprehension when motion is reduced or unavailable. Check visual states during interaction, including focus, selected, loading, validation, and failure states relevant to the task. A beautiful initial frame does not excuse unusable later states.

## 5. Critique the actual rendered result

Use the existing bounded preview allowance and current screenshots. Confirm that the intended content or WebGL scene actually rendered before judging it. Inspect meaningful desktop and narrow mobile views and the states relevant to the brief. Recompose where needed for the smaller screen; scaling down the desktop layout is not proof of fit. Check the focal subject, reading order, text wraps, negative space, reachable controls, cropping, and overlaps. Use browser_verification for measured overflow, launch routes, overlays, and action outcomes.

Base each finding on an observation: what is visible, how it affects the intended experience, and the smallest coherent correction. Distinguish a functional defect, visual craft weakness, mismatch with the brief, and optional subjective preference. For example, identify the obscured form or illegible label rather than vaguely requesting more polish. Do not replace the user's identity merely because another style is personally preferred.

For an expressive MAX website, inspect the page's supporting compositions as well as its strongest scene. If most major sections repeat thin text panels, or promised demonstrations/media are replaced by incidental marks and empty surfaces, identify the affected visible areas as a material composition/content-depth problem. Useful consistency or a deliberately typographic design can succeed when its information, hierarchy and spatial progression are developed. Do not impose an image quota or a replacement layout. A repair to contrast, a loop or an icon cannot resolve an unrelated failure of content or composition.

Prioritize blocked content, broken interactions, unreadable text, poor subject framing, and required scope before secondary styling. Group related supported corrections and inspect the changed state within the current allowance. Do not create an originality database, compulsory comparison against unrelated projects, invented numeric premium score, separate approval gate, or endless redesign loop. A limited review budget is a reason to prioritize and report remaining uncertainty, not to block otherwise authorized construction over routine creative choices.

Judge the actual first viewport after fonts and entrances settle. If the chosen hero is meant to introduce an immediate action, reserve readable room for its heading, supporting copy and primary control rather than allowing unintended line wraps to push the action below the screen. A deliberately long editorial introduction remains valid when the brief calls for it. Check diagrams and legends as visual relationships too: keep each marker, its label and explanation clearly associated at desktop and narrow widths, using the actual DOM child structure when composing their layout. Do not trade these fundamentals for more ornament or effects.

If the selected model/tool cannot inspect images or the actual preview is unavailable, use code and layout evidence only for the claims they support. Do not describe unseen colors, proportions, animation, or aesthetics as visually verified. Record that visual assessment remains incomplete. Automated layout, accessibility, imports, builds, and functional assertions are useful evidence but cannot certify premium design.

## 6. Deliver an accurate visual assessment

Explain the chosen direction and observed result in plain terms tied to this subject. For a critique, identify concrete weaknesses and useful corrections; for implementation, state which corrections were made and which rendered states were inspected. Report remaining approximations, unavailable assets, unobserved device behavior, and material limitations. Avoid unsupported claims of uniqueness, exact reconstruction, perfection, or guaranteed future quality. Preserve current evidence and distinguish a proposed improvement from a completed, inspected change.
