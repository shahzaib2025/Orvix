# Website design — Default

DESIGN DEFAULT

Apply this skill to the selected Default frontend design task. Default means normal, efficient professional execution with full creative ownership. It defines neither a visual theme nor a reusable arrangement. Do not import Medium or MAX obligations. A profile does not authorize redesigning an existing interface or expanding the human's scope.

Read visual_composition for new composition or visual refinement, and browser_verification for meaningful responsive or interactive behavior. For a defect, combine the relevant engineering guide with bug_repair. Reuse current successful reads rather than loading duplicate instructions.

## Scope and identity

Honor the current human brief, brand, references, source preferences and access mode. For open design exploration without a full-site request, build one complete section and choose its purpose from the audience and subject. Explicit full websites, applications, several sections and bounded repairs retain their requested scope. Backend work, research and unrelated requests acquire no design exercise.

Preserve identity and working contracts for repairs, additions and faithful recreations. A new folder or a familiar business name supplies no implied reference. Use the exact requested destination; request normal access when needed. Choose an unused sibling only when a newly requested folder name is already occupied, not when the human asked to work in an existing folder. Do not inspect unrelated websites, chats or source.

## Design from the information

Use the layout-first procedure in visual_composition and record the chosen relationships in the existing storyboard before source construction for a new whole website. Keep Default compact: describe the first-viewport composition, media role and how supporting content develops it. Decide what the visitor needs to understand, which evidence communicates it, and how that evidence relates to the headline, action and surrounding content. Content labels such as features, process or pricing do not prescribe separate rows, equal cards, columns or their sequence.

Choose a coherent presentation for this subject. Theme and quality words constrain the desired result; they do not select typography, media placement or geometry. A changed font, accent, illustration or animation does not make a familiar skeleton a new composition. Do not add a widget just to claim novelty.

Use existing set_design_brief and its bounded comparison when applicable. Sanitized previous-design notes are comparison evidence, not templates or permission to open other projects. If a proposal is confirmed repeated, change its actual relationships before construction. An unavailable comparison permits progress without an originality claim only before any confirmed rejection in this task. Approval belongs to its candidate; a changed proposal needs its own successful comparison after a rejection. Changed wording or a failed comparison does not clear a rejection; report an unresolved constraint when the existing comparison budget ends. Preserve ordinary useful conventions and factual content. No layout blacklist, rotation menu or extra approval stage is introduced.

## Content, media and implementation

Use supplied or verified business facts. Omit unknown endorsements, sales numbers, reviews and performance claims; a footer disclaimer does not legitimize fabricated proof. Mark ordinary illustrative examples where they appear. Keep design-process and implementation commentary out of visitor-facing copy.

Choose imagery or authored visuals that explain the subject. When product, place or people imagery matters, source suitable real images rather than filling every role with generic panels. A deliberate typographic or diagram-led concept can omit photographs. Do not present unrelated stock as the business's actual work.

Use suitable direct HTTPS image URLs by default. A URL-only request prohibits downloads. When Google images are requested, use find_visual_assets with provider:"google", inspect original sources and preserve required credits. If unavailable, report the limitation without misnaming another source or generating substitute photographs. Honor supplied local assets and explicit offline packaging. Inspect what images actually display; placeholders do not establish successful media delivery.

Implement working code in the existing stack, with readable hierarchy, responsive content, reachable controls and honest action outcomes. Use motion only when it serves the concept; neither a scroll scene nor an animation package is required. Preserve complete content and controls when motion or media is unavailable. Label local-only forms accurately.

## Finish efficiently

Use the existing bounded execution and preview allowance. Inspect the rendered composition and primary action; a build is technical evidence, not a design-quality verdict. Repair supported defects together and report remaining limits. Reuse unchanged evidence and setup. Add no critic stage, originality database or automatic polishing loop.
