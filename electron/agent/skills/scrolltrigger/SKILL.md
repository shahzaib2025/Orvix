# GSAP ScrollTrigger engineering

Use when the chosen motion genuinely depends on scroll position, entry/exit, pinning, or scroll progress. This technical skill contains no page layout, scene storyboard, or reusable design. It complements `gsap`; read both when implementing GSAP scroll motion.

## Choose triggers from real content

Register ScrollTrigger once in the website's actual runtime and coordinate related scroll-linked changes through a GSAP timeline with one clear owner. Choose a real trigger element and deliberate `start`/`end` positions based on the content's dimensions and intended reading time. Use scrub when the animation should represent scroll progress; use enter/leave actions for discrete reveals. Numeric scrub adds catch-up time, so check that it does not make the motion feel detached from the user's scroll. Avoid snapping unless it clearly serves the interaction and does not fight normal browsing.

Keep captions, stage numbers and accessible story state synchronized with the visible artwork in both directions. Timeline callbacks alone can leave a label on the wrong stage when scrubbing backwards or jumping across several beats; derive discrete state from the current rendered timeline position or use equivalent reversible state ownership. Check the same checkpoint approached from above and below. Scope each pin target to its own scene element; a repeated global selector can accidentally pin the first scene again.

When several text layers occupy one visual slot, coordinate outgoing and incoming headings with any shared base text so they do not remain superimposed after a transition settles. A static fallback must recompose the stages in natural flow or expose them through usable controls; showing only the final layer loses the intermediate content, while exposing every absolute layer in the same slot creates overlap.

Pinning is a temporary layout contract. Animate children inside the pinned element, not the pinned element itself. Before creating a pin, measure the actual fixed/sticky header bottom, usable viewport height, and the scene's content height after relevant fonts and media have settled. A `min-height: 100svh` does not prove that the contents fit. The chosen pin target and its whole readable composition must fit in the usable area with room for safe-area and visual breathing space; if they do not, recompose the scene, pin only the fitting visual while its copy stays in natural flow, or use a non-pinned responsive version. Never solve a fit problem by clipping, hiding, or shrinking essential reading content.

Account for fixed or sticky chrome in both the start position and the pinned position. Derive the offset from the real header geometry or its shared layout variable; a `top top` pin under a fixed header can lock the scene behind the header. Pin the exact scene element intended to hold position, not an oversized section that contains unrelated reading content. Keep the runway proportional to the story's actual beats instead of reusing a large fixed distance. Preserve the natural document flow outside it, and avoid nested pins, competing pins, transformed ancestors that interfere with fixed positioning, and unrelated effects attached to the same property. Use `pinSpacing` deliberately: it normally preserves the release position, but flex/absolute layouts and custom spacing need an explicit flow check.

Use responsive conditions to release or rebuild pins when the complete scene cannot fit the current viewport, including short desktop windows and orientation changes, not just narrow phone widths. A mobile fallback must be a composed natural-flow story with meaningful artwork and accessible copy, not the desktop pin removed with an undersized leftover illustration. Every scene state must remain available without motion, through natural flow or usable controls. Do not hijack scrolling or force users through empty runway to reach content.

Cover the complement of the pin condition explicitly: wide-but-short windows can match neither a wide-and-tall desktop branch nor a narrow-screen branch. All such sizes still need readable natural-flow content, final counters and complete diagrams. Treat pin eligibility as a measured fit decision, separate from whether the section's information is initialized. Reserve space below the real header; a tall scene with a 100vh minimum can still overflow while pinned.

CSS height changes alone do not disable a JavaScript pin. Rebuild or revert its owning responsive GSAP context when actual content cannot fit after resize, zoom, font/media loading or a changing story state. Keep supporting reading outside the pin or use multiple readable states instead of forcing all detail onto one screen. Use the existing preview's measured viewportFit failures during active story checkpoints; a partially visible element is not a fitting scene. Preserve meaningful mobile and reduced-motion content without expanding the existing inspection budget.

## Measurement, refresh, and cleanup

ScrollTrigger calculates positions from document geometry. Refresh after fonts, image decoding, and meaningful dynamic or responsive layout changes; coalesce related refresh requests rather than refreshing every frame. Create triggers in a deliberate order when upstream pins change downstream offsets, then refresh after the complete timeline is assembled if the geometry depends on it. Use a custom scroller only when the page actually scrolls inside a custom container. If paired with Lenis, also read `lenis` and follow its current official integration so scroll updates share a coherent clock.

Scope triggers to the page/component lifetime. Revert the owning GSAP context or kill only the triggers the component owns on teardown/navigation. Responsive changes must not accumulate duplicate triggers, pin spacers, listeners, or callbacks. Preserve ordinary content visibility when trigger initialization fails.

## Inspect real scroll states

Use actual changed elements as observed selectors: a stationary parent panel does not prove its children or story state changed. Within the existing preview budget, inspect the pin's approach/start, an active story state, and its release; include reverse/re-entry when supported. Check measured bounding boxes during the active pin: the scene must clear the real header, fit the usable viewport, and leave following content in the intended document position after release. Inspect regular unpinned reading sections too; a working pinned scene does not establish page-wide behavior. When a section appears blank, inspect parent and child computed opacity/visibility and distinguish hidden content from an unloaded image or artwork that is simply too small. Check short desktop height, mobile pin release, reduced-motion content, browser errors, and the final primary action where relevant.

Treat screenshots and automated layout findings as evidence only for the states captured. Do not claim complete scroll behavior from a build, from one screenshot, or from a trigger merely existing in source. Consult the current [official ScrollTrigger documentation](https://gsap.com/docs/v3/Plugins/ScrollTrigger/) for API and version-specific behavior.
