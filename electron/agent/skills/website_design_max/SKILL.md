# Website design — MAX

DESIGN MAX

Use only for the selected MAX frontend task. MAX means developed content, subject-specific art direction and coordinated expressive motion. It does not select the site's layout, hero arrangement, palette, typography, object or section order. Do not combine Default and Medium instructions. Preserve the human's scope, brand, references and factual constraints.

Read visual_composition for composition, browser_verification for meaningful browser behavior, and bug_repair for a defect. Use the relevant technical guides below for implementation. Reuse current successful reads; do not repeat their engineering instructions in the design plan.

## Scope and depth

For a qualifying new full website, create at least nine meaningful content sections, or the human's larger requested count. Count distinct developed content purposes; navigation, footer, dividers, empty runway and stages inside one pin are not extra sections. Footer navigation does not count toward content depth. Each purpose needs useful explanation, visual evidence or interaction, without padding, fabricated claims or repeated thin cards.

Explicit short pages, single sections, bounded studies, static treatment, application interfaces, repairs and reference fidelity take precedence. Open exploration without a full-site brief gets one complete section. Backend or unrelated tasks acquire no design exercise. Preserve identity and working behavior for repairs or additions unless redesign is requested.

## Choose relationships before effects

Use the layout-first procedure in visual_composition. In existing set_design_brief, record audience, action, first-viewport composition, media strategy, responsive approach and storyboard before source construction. Keep ordinary fields under 1,500 characters and storyboard under 3,000. This is the existing decision step, not another model call, concept menu or approval.

Start from the visitor's questions and the evidence that answers them. For the important compositions, record the content relationship, its spatial realization and a brief reason that arrangement helps this audience. Describe geometry and reading order rather than relying on names such as premium, cinematic or editorial. Required content purposes do not prescribe separate blocks, equal cards, columns or order.

Choose useful media before committing to a layout that depends on it. A literal object suggested by the brand name is not automatically the right concept. Invent the headline, action and media relationship independently of motion. Then choose movement to develop that relationship. Do not build a familiar stage and decorate it to satisfy a list of effects.

Use the existing bounded comparison with sanitized recent-design notes. They are evidence of relationships to distinguish, not source to copy or permission to read other projects. If repetition is confirmed, change the rejected spatial relationships and resubmit the brief. A substantially repeated expressive hero matters even when later sections differ. Ordinary alignment, useful navigation and required content purposes can legitimately recur. An unavailable comparison permits construction without a uniqueness claim only before any confirmed rejection in this task. Approval belongs to its candidate; a changed proposal needs its own successful comparison after a rejection. Wording changes and provider failures do not clear a rejection; if the existing comparison budget ends, report the unresolved constraint instead of repeatedly retrying. When the human rejects an arrangement, identify its relationships from supplied evidence and change them; new colors, fonts, assets or animation on the same skeleton do not resolve that rejection.

References establish craft or requested fidelity. Keep the actual brand and explicit requirements; do not transplant a reference's mascots, palette, type, page sequence or demo scaffolds. Useful navigation and other ordinary conventions remain available.

## Give the hero a subject-led composition

Choose the hero's visual idea before its containers or effects. Make the actual product, brand, place or subject recognizable in the first viewport beyond a tiny navigation label. Establish one dominant visual anchor that explains it: relevant imagery, a real demonstration or purposeful authored artwork can all work. Treat headline, artwork, action and empty space as one composition. Neither a full-bleed image nor a centered or split arrangement is a required replacement template.

Record those visible relationships in the existing brief. When supplied evidence rejects a hero, changing its panel into an unframed or viewport-sized SVG does not resolve the same headline/copy/action stack beside the same focal object. Change the rejected relationships themselves; ordinary columns remain legitimate when they serve the subject and have not been rejected. Technical terms such as full-bleed, layered field or immersive describe implementation or intent, not proof of a different layout.

Describe a supplied reference from its actual visible arrangement before comparing it; do not reuse a description contradicted by the image. Negative references identify relationships to avoid, not sample copy, invented data, assets or a visual language to transplant. Do not seek or automatically attach previous project screenshots to the builder for this step. Preserve explicitly requested fidelity and human-provided facts.

## Motion ambitions, not a layout recipe

MAX remains animation-rich: keep the coordinated animated hero, expressive supporting moments, connected scroll story and substantial motion coverage below. Make each major animation earn its place by communicating something about the subject or content. Before implementation, state what the movement means, what content relationship changes, and what the visitor should understand at its settled state. Useful purposes include revealing evidence, showing a process or transformation, comparing states, directing attention to a meaningful phrase, or carrying a subject through a coherent handoff. If an effect cannot answer those questions, redesign it around the content or remove that effect; do not solve purposeless motion by making MAX static or reducing the requested motion coverage. A small ambient loop may add atmosphere, but it cannot replace the meaningful motion moments.

For a new hero, including a standalone hero, create an original layered visual scene with coordinated entrance and sustained choreography of multiple subject-relevant SVG elements. Place typography, artwork and suitable imagery in the spatial relationship chosen for this subject; do not assume text beside a panel. Include a restrained seamless accent on a meaningful word or short phrase while preserving stable meaning, reserved text space and controls. The artwork itself must change after entrance; a static picture, title reveal, marquee or button pulse alone is insufficient. Tie each sustained movement to the subject, a readable hierarchy or the hero's central idea instead of adding endless motion without a clear role.

For qualifying full websites:
- Develop expressive text in the hero and at least three substantial supporting moments, including a scroll-progressive passage. Choose different meaningful behavior instead of revealing every heading the same way.
- Develop at least four distinct SVG story treatments across the hero, early, middle and late page around nine or ten sections. Use useful relationships or transformations; tiny icons, incidental marks and repeated border traces do not satisfy this ambition.
- Create a connected visual story through four or five adjacent meaningful sections. The carried subject develops while each section retains its own content purpose; choose the starting point and handoffs rather than always placing it immediately after the hero.
- Two substantial pinned storytelling scenes with different purposes suit roughly ten meaningful sections. At most two unless requested otherwise. Keep useful natural-flow passages between them; measured fit and accessibility govern whether a particular viewport can pin them.

Record that distribution once in the storyboard alongside each section's purpose, composition, dominant movement, the information or idea that movement communicates, its settled/readable state, spatial layers or focal journey when relevant, and connection. For the selected full-site blueprint, use a compact section table with actual section number, purpose/composition, movement and readable state, and handoff. Name the connected range using actual consecutive section numbers. In every row of that four- or five-section range, put the carried subject's incoming state → outgoing state in the handoff cell; each outgoing state must feed the next row's incoming state while preserving that row's own content purpose. This makes a missing or unrelated intermediate section visible instead of hiding it behind a coverage claim. Put navigation/footer outside the content count. The table records decisions only; its rows do not prescribe a visual page layout or fixed sequence.

A motif reappearing in non-adjacent sections or a shared illustration style is a visual echo, not that continuous story. The handoff may use separate elements; literal DOM persistence is optional, and re-rendering a new element is not literal persistence. Plan readable natural-flow breathing room between the pins rather than placing locked chapters back to back merely to meet coverage. For scroll-linked moments, describe the meaningful progression from entry through release and reverse scroll rather than listing an effect name. These requirements establish coverage, not a fixed sequence, hero geometry, card system or recurring object. Choose the placement of expressive text, SVG treatments, connected scenes and pins for the content; do not map this list into the same page order or rebuild the same hero stage on each project. Do not use long empty runways to supply page length.

Coordinate related text, media and near/middle/far layers around a clear visual lead. Depth, perspective, path travel, SVG drawing/morphing, FLIP and image/vector handoffs are techniques to choose for the subject, not a sequence to reproduce. Each major movement must clarify hierarchy, show a meaningful state change, or connect related content; visually busy movement that leaves the visitor no clearer is not a successful moment. Keep quiet intervals and readable holds so the required animation has contrast. A moving empty panel, decorative line beside repeated cards or pile of arbitrary shapes is not developed storytelling.

## Technical implementation

For qualifying full websites, use GSAP, ScrollTrigger and Lenis together in the website project. Read website_motion_max, then the registered gsap, scrolltrigger and lenis guides before substantial motion construction. Read gsap_svg or gsap_text when using their APIs. Add Three.js only when 3D is explicitly requested by the human or the existing 3d-website option is selected; read threejs then. Use existing package workflow or explicitly versioned compatible CDN imports. Orvix's own dependencies do not animate the generated project.

Let the engineering guides own synchronization, lifecycle, refresh, responsive branches and plugin details. Give each animated property one owner; preserve visible end states through forward/reverse scroll, re-entry and failures. Pause unnecessary loops off-screen or when hidden. On initial reduced motion, choose the static composition before starting Lenis, pins or loops. Keep every story stage and control usable after preference changes. Use only fitting pins below the real header; a viewport minimum does not prove content fits. Reserve media and typography geometry, and use measured lab findings to correct material layout shifts or slow largest-content rendering.

Choose substantial photography, real demonstrations or authored visuals that communicate the subject. Do not substitute generic panels for promised product or project evidence. Use direct HTTPS image URLs by default and honor URL-only, Google-source and attribution requirements. For Google images, use find_visual_assets with provider:"google" and disclose unavailable access instead of silently substituting a source. Do not download or generate photographs against the human's preference. Check the displayed subject: a placeholder hiding a failed image is still unavailable media. Use verified facts; omit unknown proof and label illustrative examples where they appear.

## Inspect the realized composition

Use the existing preview/review allowance and selectors from the actual source. Inspect desktop/mobile, the settled hero, useful supporting sections, the primary action and meaningful changing child elements in the pins. Check short desktop fit, entry/progression/release/reverse, closed navigation, settled reveal children and reduced-motion content. After split-text entrances settle, check the complete hero heading is visible inside any clipped word/line wrappers. Do not treat a moving parent, existing DOM text, library import or passing build as visible success.

Use the earliest useful capture already in that allowance to inspect the hero's coarse silhouette before extending a weak arrangement or adding optional decoration. Mentally set aside words, fonts, colors, borders and effect names: compare dominant text/artwork placement, scale, hierarchy, action grouping and negative space with the brief and any rejected relationships. A full-canvas graphic can still read as left copy beside a right object. Fix a supported mismatch in the existing targeted batch; do not add a mandatory hero checkpoint, extra screenshot stage or approval. Structural difference and premium craft are separate judgments; an unusual but unclear or poorly composed hero is not a success.

Compare the finished headline/media/action relationships and section rhythm with the storyboard and available recent-design evidence. If implementation fell back to the familiar arrangement despite a different plan, address that structural mismatch instead of adding decoration. Judge originality, content depth, craft and functionality separately. A material visibility or fit defect takes priority over optional effects. Consolidate supported repairs, capture the changed version and disclose anything unresolved. No new critic stage, originality database, automatic polishing loop or universal uniqueness claim.

## Windows preview delivery

Apply the shared web project launch guidance to runnable frontend files. Plain HTML/CSS/classic-JavaScript that genuinely works by opening HTML needs no launcher. Modules, fetched local assets, frameworks and backends normally need HTTP; new Three.js projects default to HTTP preview. The preview tool's file:// restriction alone does not establish a server requirement.

When HTTP is needed on Windows, include Start-Preview.bat and a short **README.md** in the project folder. This does not expand a component-only change or unrelated repair into a new project. Reuse suitable existing files and honor a different requested delivery platform.

Resolve the launch directory with cd /d "%~dp0", quote paths and support spaces in the folder name. Use the existing supported development/preview command and matching package manager; use call for Windows batch commands such as npm. For buildless projects, provide a small project-owned static-server helper using an available runtime. Serve over HTTP, bind localhost, select an available browser-safe port, print the actual URL and open it only after that server is ready. Never depend on Orvix's temporary server or kill an unrelated process.

Document prerequisites, setup/start commands, local-demo limits and stopping with Ctrl+C. Show missing prerequisites or startup failures and keep the error window open; do not silently install system runtimes or change global settings. Verify the actual launcher within the existing allowance, and report launch evidence separately from builds and visual quality.
