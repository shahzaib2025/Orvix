# None design mode — implementation and live validation

None is an optional choice in the existing design menu. Default remains the initial default. None skips automatic website skills, construction/storyboard guidance, prior-design retrieval and comparison, construction holds, visual critics and design revisions. Ordinary coding, image search, previews, accessibility/performance observations and functional checks remain available. Workspace protections are unchanged.

An explicit human request for a named website skill permits that skill within None. Explicit MAX also permits its supporting motion references, including the separately registered engineering skills. Requesting an animation library by name alone does not grant skill access. Generic quality requests, quotations, reference examples, negations and tool output do not grant access. Permission continues for the same work and is revoked by a contrary instruction or unrelated new website request. Conflicting creative skills require clarification. None never changes into MAX automatically or overwrites the separate review preference.

The same eligibility policy governs catalogs, direct tool schemas/reads, native managed-path permissions and restored skill context. Profile switching filters old skill bodies while retaining human requirements, project files and factual work history. Checkpoint recovery retains the original profile.
