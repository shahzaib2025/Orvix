# Live screen sharing

The Home input has a round eye button outside its right edge. The existing input size is unchanged. In narrow layouts the button sits above the right edge to avoid clipping or shrinking the input. The button works for Fast and Thinking in Electron.

Click the eye, choose a screen or window, then ask a question by typing or using the microphone. With voice active, say **“screen e dekho”**, **“screen share on koro”**, or **“স্ক্রিনে দেখো”** to open the source chooser; choose the screen you want Orvix to see. Say **“screen share off koro”**, **“stop screen sharing”**, or **“স্ক্রিন শেয়ার বন্ধ করো”** to stop sharing. Start commands never choose a source for you. The eye button opens the chooser and stops an active share. Use the chooser's close button or Escape to cancel. The active button glows green while sharing. New chats, profile changes, navigation away from Home, ended capture tracks, session errors, and app teardown release capture. Microphone access is controlled separately by the microphone button.

Only the explicitly selected source is granted to the main workspace. Other windows/frames cannot request capture; system audio is excluded. Source selection is consumed once and expires after ten seconds. If the source disappears or permission is denied, capture stops and a visible error is shown.

The renderer captures locally at up to 5 FPS to keep the sampled bitmap current and sends at most one JPEG video frame per second to the Live connection. Output preserves aspect ratio, never upscales, is bounded to **2560 × 1440**, and uses JPEG quality **0.9**. Fast and Thinking configure `MEDIA_RESOLUTION_HIGH`. The freshest eligible frame is also paired with typed questions or the onset of spoken questions. A frame older than 3.5 seconds, or dated in the future, is rejected. When a fresh image is unavailable, previous images are explicitly identified as historical; unreadable text requires a clearer view. Frames stay in memory, are cleared on stop, and are not written to conversation history or logs. Screen content is untrusted observation; Orvix waits for a question rather than narrating frames automatically.

The local preview shows the **same processed JPEG accepted by the active Live session**, with source, dimensions and stale state. A selected display is captured in full. The pet stays visible locally. The main process enables capture protection before sharing and waits 200 ms for desktop composition. A per-frame guard verifies native exclusion or returns a display-relative mask covering current and recent pet bounds. Masking happens before JPEG encoding. Lease IDs prevent delayed cleanup from removing newer protection.

On this Windows 10 build 19045 host, Electron did not confirm native exclusion for the transparent pet window. The full-display masking fallback is therefore used, labeled **Pet area masked** in the preview. Content behind the mask is unavailable to Orvix; move the pet away from details you want read. Window sharing stops if native exclusion cannot be confirmed and a safe mask cannot be established; choose a full display instead. Workspace hide, renderer loss/navigation, suspend, reconnect and app shutdown also release capture/protection. A recreated pet inherits the active protection setting.

Electron's empty-`mediaTypes` display permission is allowed only for the main frame with an explicitly selected source and an active exclusion lease. Camera capture and system audio remain denied.

Focused checks cover selection, cross-window rejection, audio denial, exclusion leases/fallback, cancellation, dimensions/aspect ratio, JPEG quality, cadence, identical preview frames, stale/future frames and cleanup. Thinking protocol checks cover the underlying Live connection and recovery. The broader Fast suite has 40 existing failing cases: the same failure names were reproduced against an isolated copy with the screen-sharing Fast edits reverted. See `scratch/screen-sharing-fast-current.log` and `scratch/screen-sharing-fast-baseline.log`; the focused checks do not imply that broader suite passes.

The native harness loads the packaged main/preload/renderer under the same Electron version with isolated user data. Its `--packaged` option launches the actual `Orvix.exe` and asserts its isolated user-data path. It captures an actual Windows display containing a controlled HTML form and diagram window, rather than submitting a generated JPEG. A visible magenta pet marker is counted before and after masking. Raw screenshots remain in memory; reports contain answers and numeric measurements. The live benchmark asks typed questions and counts PCM output. It does **not** validate a physical microphone or speaker. The earlier generated-card report only proves generated-image recognition.

## Results on 2026-10-07

- Production build and directory package succeeded. **39 focused capture/Thinking protocol checks passed**, and the Thinking flow checks passed. Voice controls recognize explicit English, Banglish and Bangla phrases; completed Fast and Thinking control utterances are consumed without becoming ordinary assistant questions.
- Actual 1366 × 768 Windows display capture: 57,105 visible marker pixels in the baseline, **zero** in the processed frame. The pet stayed visible locally, and preview JPEG equality passed. The masking fallback was used; native exclusion was not confirmed.
- **Fast 20/20, Thinking 20/20** known-answer values matched, including 14px labels, 16px form values, codes, numbers and diagrams. These results apply to this controlled desktop fixture, not every arbitrary screen.
- Both profiles refused to supply a value for unreadable 1px text, a stale image and sharing off: **6/6 checks passed**. The final Thinking refusal was in Bangla; the report preserves the answer and explains the bilingual grading correction.
- The actual packaged executable passed the typed start/stop commands, eye-button stop, full-display picker, preview and Stop sharing control. Preview staleness, profile changes, new chats and navigation cleanup also passed; capture protection was restored after stop.
- The live run exposed and fixed a Thinking routing error: current visible UI values no longer require unrelated web research. Explicit online research still does.
