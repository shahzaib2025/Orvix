# Bounded website design comparison

## Behavior

Fresh whole-website requests now compare their proposed composition against up to four recent design briefs persisted in existing task memory. Up to 128 recent task files are considered; no new settings, template library, database, chat-history injection or project-code scans are introduced. The current task's earlier design is included for an explicit fresh-site request, but excluded on resume. Continuations, existing-site repairs, redesigns, app interfaces, section experiments and requested reference copies preserve their scope.

An identical direction/storyboard is rejected locally. Paraphrased directions receive a bounded semantic comparison using the selected model and reasoning variant. Rejection needs concrete similarity in at least two composition dimensions, including hero or page structure. A shared theme, subject or normal usable controls is insufficient. The model invents the replacement; no predefined alternatives are supplied.

Before acceptance, native write/edit/patch permissions and non-setup shell commands are held. Direct-route source tools and executable project operations are likewise held. Native visual preview-server execution also cannot bypass acceptance. Directory creation, bounded discovery and image research remain available. The brief tool awaits comparison before recording an accepted direction; rejected directions are not committed. Identical proposals reuse their result, with at most three semantic proposals per run. Invalid/unavailable comparison results keep construction blocked and report the limitation.

The existing independent visual review now receives recent composition records plus up to two available previous screenshots, clearly labelled as comparison evidence rather than templates. Fast mode uses its bounded independent review when comparison records exist. Explicit off mode retains its existing no-review behavior, so it does not establish final visual diversity. No additional revision loop is introduced. The old three-concept instruction in the tool description was removed.

## Validation

Focused and routing/browser checks cover identical and paraphrased repetition, materially different composition with a shared theme, missing/malformed provider responses, cancellation, attempt budgets, scope exclusions, bounded memory retrieval, missing images, earlier-site visual-review inputs, and actual native permission gating through the tool bridge.

Live Muse Spark 1.3 Contributor Free, medium reasoning (matching the two supplied runs): the new semantic gate rejected the actual repeated Shop 2/Messages composition in 9.225 seconds and accepted a deliberately different composition control in 7.745 seconds. These were live composition comparisons, not new website generations. Evidence: scratch/design-diversity-live-1791726074397/report.json.

## Limits

This enforces bounded recent-design comparison; it is not a guarantee against every historical or unseen website. Semantic and visual comparison can misjudge similarity, and a model can implement a different composition than its brief; the existing visual review checks that gap against supplied samples. Missing images leave text-only earlier evidence, explicitly described in the review prompt. Concurrent brand-new tasks can start before either has persisted a comparable design. User-requested copies and continuity are intentionally exempt. A full new-site generation has not been run for this change.
