# Design profiles: implementation plan

1. Add validated creative profiles `normal`, `medium`, `max`. Default uses the normal skill; Medium adds deliberate section rhythm and light motion; MAX adds autonomous art direction, varied section compositions and a meaningful signature scrolling/interactive scene for substantial showcase builds. No fixed palette, layout, section count or recurring scene template.
2. Route the profile through UI/task/turn persistence, IPC, direct model requests, native initial/revision/retry instructions and checkpoints. Start the versioned preference at Default. Display legacy Fast as Medium, Balanced/Thorough as MAX and Off as Default without rewriting old evidence. Preserve resumed execution settings.
3. Keep creative profile separate from review policy. Following the user's request for speed and fewer checks, new profiles use builder inspection by default. Do not add mandatory independent critic passes or originality-history databases; explicit legacy review choices remain compatible.
4. Add bounded scroll-story inspection to the existing preview tool: measured scroll progress, labelled images with animations enabled, actual visible text/media/styles/positions, forward/reverse or wheel sampling, and reduced-motion/mobile support. One evidence bundle; no arbitrary model-supplied JavaScript, mandatory video recording or continuous smoothness claims.
5. Add optional compact storyboard details to the existing brief tool and expose the profile in verification. For MAX, instruct the builder to inspect its chosen scene with the motion tool when available, preserving accessible fallback and working actions. Small repairs, dashboards and faithful recreations preserve scope.
6. Verify routing/migration/retry/resume behavior, real pinned-sequence observations, reverse/release and fresh browser contexts, then run existing regression checks and build. Only after those pass run a real MAX generation and inspect its screenshots separately.

No global GSAP/animation dependency is needed. Use the generated project's stack and the lightest technique that serves its own idea. The earlier MAX-level brief test was stopped before these profiles existed and is not a MAX-mode result.

## Implemented behavior and validation

The profile selector, versioned preference, per-task/turn settings, direct/native routing, checkpoint profile, optional storyboard, profile display and bounded motion preview are implemented. Historical review choices remain compatible; new profile selection uses fast builder inspection. A requested MAX scroll sequence gets at most one additional motion-capture reminder and is reported unavailable if fresh sampled states are missing. This is evidence of sampled progression, not a guarantee of global originality, smooth frame rate, or premium aesthetics on every run.

Motion capture accepts one to six checkpoints, at most two viewports and six observation selectors, a maximum 500 ms settling interval, a 20-second per-viewport budget and bounded screenshots. It uses existing local-preview permissions and navigation restrictions. Each labelled frame includes actual scroll position, visible text, element bounds/styles and relevant image sources. The browser still uses fresh contexts, and the existing 200K compaction policy is unchanged.

Validation completed: 6 profile/motion checks, 10 design-review checks, 42 native/precision checks (including MAX guidance in initial and acknowledgment-retry prompts and the retained MAX profile on direct resume), the browser UI navigation/session fixture including MAX selection and dispatched profile, 98 broader agent regression checks, and application build. Some suites overlap; these counts are not summed as unique tests. The build retains large-chunk warnings. A real MAX site generation is recorded separately; a passing fixture is not claimed as an actual generated-site result.
