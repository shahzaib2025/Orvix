# MAX page depth and inspection corrections

## Observed White Atelier result

The generated page has six HTML sections, not only three or four. Desktop height was 6,643px, of which 3,060px (about 46%) belongs to the pinned story runway. Supporting chapters are mostly a short split introduction, a three-card library, a form and four occasion cards. Their animation is largely entrance reveals. The main pin changes text around the same rose photograph. Physical page height therefore overstates its content and visual depth.

Read-only desktop/mobile/reduced-motion inspection found a working local composer, no document overflow, no broken images and no page errors. Motion sampling observed story text progression and reverse. These observations do not establish a premium design or continuous animation smoothness. Screenshots and observations are in scratch/atelier-max-inspection/Comparison.

The run's originality guard rejected its original repeated split-hero proposal, then accepted a different centered direction. That is live evidence of the new guard affecting builder behavior. It does not establish that the replacement is rich enough for MAX.

## Implemented

Only MAX guidance and its compact execution reminder now explicitly require a substantial long-form experience for an open complete website brief. Supporting chapters must develop their content and composition, with multiple substantial unpinned experiences and meaningful connected motion. A hero plus thin blocks, repeated grids, a form or a long pin runway is insufficient. No fixed count, page map, visual theme, animation catalog or fabricated facts are imposed. Scope exceptions remain intact.

The existing independent review now receives MAX-only content-depth acceptance criteria: skeletal or repetitive supporting chapters are a major content_depth/composition issue rather than an optional cosmetic preference. Default and Medium do not receive those added criteria. No extra critic or polishing loop is introduced.

MAX guidance also specifies final motion sampling after the last source edit in the existing capture budget. The user's run had actual changing motion frames, but a later CSS edit changed the source fingerprint and its final capture omitted motion. Its final motion acceptance was consequently unavailable; old evidence was not falsely treated as current. This freshness protection remains intact.

The failing layout entries were caused solely by intentionally off-screen keyboard skip links targeting the composer section. The existing checker only recognised main-container targets. It now recognises a valid section/form or main-descendant destination only when keyboard focus actually makes the link visible and usable in the viewport. A regression test retains failure for an off-screen link that remains unusable on focus.

## Validation

60 profile, review, skill, diversity and visual-tool checks passed. An additional focused test passed verifying that complete MAX review receives the new depth criteria while Default/Medium do not. Syntax checks passed. Actual current-site capture with the updated checker returned no clipped content, no overflow, no broken images and four motion samples at desktop/mobile viewports. The site source was not changed.

No new website was generated under these updated MAX instructions. Restart Orvix before the next test. The changes strengthen generation and acceptance guidance, not a guarantee of model taste or exceptional outcomes every run.
