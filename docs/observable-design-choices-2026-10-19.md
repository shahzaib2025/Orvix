# Observable design alternatives

The shared visual composition skill now asks open-ended new websites and standalone heroes to record two short spatial options, the selected option and a content-based reason in the existing storyboard. The selected plan comes first so bounded evidence retains its construction instructions. Alternatives are labeled as decision evidence, with the unselected option explicitly excluded from construction. No new fields, model stage, settings or public concept menu were added.

The compact execution reminder and existing construction feedback reinforce this for open creative briefs. Explicit human layouts, faithful recreation, repairs and additions retain their scope; None does not acquire the automatic workflow. Both proposal comparison and rendered-composition instructions judge the selected plan and ignore the discarded option as a construction requirement.

## Remaining weaknesses

- Generation is slow and placeholder navigation remains in both prototypes.
- First run's recorded user-flow failures used `kind:visible, expected:false`; the current browser-workflow implementation treats kind `visible` as requiring visibility, so those assertions fail even though the dialog closed. Independent dialog checks passed. The original failed verification status is preserved, not rewritten as a pass.
- Second run's final lab performance check failed: LCP 4,420ms, transferred 936KB. Later successful functional assertions do not clear the performance failure.
- Neither prototype is accepted as a fully verified production website. The positive result here is observable planning, successful repeat detection and a different final realized composition.
